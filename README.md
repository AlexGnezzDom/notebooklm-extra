# notebooklm-extra

**MCP-сервер для Google NotebookLM (Gemini Notebook): вопросы по источникам, чтение и массовая выгрузка содержимого, артефакты Студии.**

> *MCP server for Google NotebookLM — ask grounded questions, read and bulk-export source contents, manage Studio artifacts (mind maps, reports, flashcards, quizzes). Self-contained: no other package required.*

---

## Зачем это нужно

У NotebookLM **нет публичного API** — есть только Enterprise-версия, требующая Google Cloud и лицензию Gemini Enterprise. Поэтому доступ к личному блокноту возможен лишь через браузерную автоматизацию.

Этот сервер — **самодостаточный**: собственная авторизация, ничего больше ставить не нужно.

Он умеет то, чего не умеет ни один из известных аналогов: **прочитать текст источника**, **выгрузить весь блокнот на диск** и **создать артефакт Студии** — ментальную карту, отчёт, карточки, тест.

## Что умеет

| Инструмент | Назначение |
|---|---|
| `nlm_setup_auth` | Разовый вход в Google |
| `nlm_ask` | Вопрос по источникам блокнота с полным ответом |
| `nlm_add_source` | Добавить источник по ссылке (сайт, YouTube) |
| `nlm_health` | Проверка реального доступа к блокноту |
| `nlm_list_sources` | Список всех источников с номерами |
| `nlm_read_source` | Полный текст одного источника |
| `nlm_download_notebook` | Выгрузка всех источников в `.md`-файлы |
| `nlm_list_artifacts` | Список артефактов Студии |
| `nlm_create_artifact` | Создание артефакта (9 типов) |

**Типы артефактов:** Ментальная карта · Отчёты · Карточки · Тест · Инфографика · Таблица данных · Презентация · Аудиопересказ · Видеопересказ

## Требования

- **Node.js 20+**
- **Google Chrome** (используется реальный браузер)
- Аккаунт Google с доступом к NotebookLM

## Установка

### 1. Скачать и собрать

```bash
git clone https://github.com/AlexGnezzDom/notebooklm-extra.git
cd notebooklm-extra
npm install
```

### 2. Подключить к клиенту

**Claude Code** — в `~/.claude.json`:

```json
{
  "mcpServers": {
    "notebooklm-extra": {
      "type": "stdio",
      "command": "node",
      "args": ["/абсолютный/путь/notebooklm-extra/src/index.mjs"]
    }
  }
}
```

**Claude Desktop** — в `claude_desktop_config.json`, блок `mcpServers` тот же.

Перезапустите клиент.

### 3. Войти в Google — один раз

Попросите клиента: **«Авторизуй notebooklm»** (инструмент `nlm_setup_auth`). Откроется окно Chrome — войдите в аккаунт, окно закроется само.

Профиль сохраняется в каталоге данных ОС (`~/Library/Application Support/notebooklm-extra` на macOS), поэтому переустановка репозитория авторизацию не сбрасывает.

> Если вы раньше пользовались `notebooklm-mcp`, его профиль импортируется автоматически — входить повторно не нужно.

## Использование

Естественным языком — клиент сам подберёт инструмент:

```
Покажи источники блокнота https://notebook.google.com/notebook/<uuid>

Спроси у блокнота, какие три главных вывода делает автор

Прочитай источник №5

Выгрузи весь блокнот в файлы

Создай ментальную карту по блокноту
```

### Пример: выгрузка

```json
{
  "name": "nlm_download_notebook",
  "arguments": {
    "notebook_url": "https://notebook.google.com/notebook/<uuid>",
    "limit": 5
  }
}
```

Результат — папка `downloads/notebook_YYYY-MM-DD/` с `.md`-файлами и `_index.md`.

## Настройка (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `NLM_SOURCE_PROFILE` | каталог данных ОС | Профиль с куками Google |
| `NLM_OUT_DIR` | `./downloads` | Куда сохранять выгрузки |
| `NLM_HEADLESS` | `true` | `false` — показывать окно браузера |
| `NLM_WINDOW_WIDTH` | `1600` | Ширина окна в headless. Ниже ~1300 интерфейс схлопывается в табы |
| `NLM_WINDOW_HEIGHT` | `1000` | Высота окна в headless |
| `NLM_SETTLE_DELAY` | `5500` | Пауза после загрузки страницы, мс |
| `NLM_READ_DELAY` | `3500` | Пауза после клика по источнику, мс |

На медленном соединении увеличьте задержки.

## Как это устроено

```
nlm_setup_auth ──► профиль с куками (каталог данных ОС)
                          │
                          ▼
              Chrome (Patchright) ──► notebook.google.com
```

**Почему один профиль, а не копия.** Google ротирует куки сессии: копия получает свежие, оригинал остаётся со старыми — и те становятся недействительными, требуя повторного входа через раз. Поэтому работаем с оригиналом, а одновременные вызовы выстраиваются в очередь внутри сервера.

**⚠️ Не держите второй коннектор к NotebookLM.** Две браузерные автоматизации под одним Google-аккаунтом Google считает параллельными сессиями и сбрасывает обе. Если раньше стоял `notebooklm-mcp` — отключите его.

## ⚠️ Ограничения и риски

**Это браузерная автоматизация, а не API.** Отсюда следствия:

- **Хрупкость.** При редизайне NotebookLM селекторы ломаются. Чинится — см. ниже.
- **Ширина окна критична.** Ниже ~1300px NotebookLM схлопывает колонки в табы «Источники / Чат / Студия», и список источников исчезает из DOM — инструменты вернут ноль. В headless размер задаётся явно (`NLM_WINDOW_WIDTH`).
- **Скорость.** ~5–10 сек на источник. Блокнот из 50 источников выгружается 5–9 минут.
- **Условия Google.** Автоматизация интерфейса может противоречить [Google Terms of Service](https://policies.google.com/terms). Используйте на свой риск и только со своими данными.
- **Лимиты.** Бесплатный тариф NotebookLM: 50 запросов/день, 100 блокнотов, 50 источников на блокнот.
- **`nlm_create_artifact` запускает генерацию, но не ждёт результата** (1–10 мин). Проверяйте через `nlm_list_artifacts`: пока идёт генерация, название артефакта — «Создаем ментальную карту…», по готовности меняется на настоящее.

**Что проверено.** На живом блокноте из 296 источников прогнаны: вход, вопрос по источникам, список и чтение источника, выгрузка на диск, создание ментальной карты и карточек, их появление в Студии. Единственный инструмент без сквозной проверки — `nlm_add_source`: он изменяет содержимое блокнота, и тестировать его на чужих данных мы не стали.

### 🔐 Безопасность

Профиль содержит **cookies вашего Google-аккаунта**. Папка `profile/` в `.gitignore` — **никогда не коммитьте её и не передавайте третьим лицам**. То же касается `downloads/` — там ваши данные.

## Починка селекторов

Если после обновления NotebookLM инструменты перестали находить элементы:

```bash
NLM_HEADLESS=false node tools/probe-ui.mjs "https://notebook.google.com/notebook/<uuid>"
```

Скрипт покажет структуру DOM и кандидатов на селекторы. Обновите блок `SEL` в [`src/config.mjs`](src/config.mjs).

Текущие селекторы:

```js
sourceRow:         ".single-source-container"          // строка источника
artifactItem:      "artifact-library-item"             // артефакт Студии
artifactTitle:     ".title-container"                  // название артефакта
docViewer:         "labs-tailwind-doc-viewer"          // просмотр документа
createArtifactBtn: ".create-artifact-button-container" // кнопка типа в Студии
chatInput:         "textarea.query-box-input"          // поле вопроса
chatMessage:       "chat-message"                      // сообщение чата
```

Четыре ловушки вёрстки, на которые стоит обратить внимание при починке:

- **Ширина окна — часть контракта.** На узком экране нужных элементов нет в DOM вообще, и это неотличимо от «сломался селектор».
- **Кнопки Студии — не `<button>`,** а `div` с `aria-label`. Искать по роли кнопки бесполезно.
- **Подтверждение генерации ищется по точному совпадению.** Поиск по вхождению «Создать» цепляет «Создать блокнот» в шапке — вместо артефакта создаётся новый блокнот.
- **Конец ответа определяется по панели оценки** под сообщением, а не по тексту. Формулировки промежуточных статусов меняются («Поиск ответов…», «Выполнен поиск в ваших источниках…»), и ловить их перечислением бесполезно — а кнопки «нравится / не нравится» появляются ровно тогда, когда генерация закончена.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| `Нет авторизации` | Первый запуск — вызовите `nlm_setup_auth` |
| `Сессия Google истекла` | Google сбросил куки — вызовите `nlm_setup_auth` заново. Если повторяется — проверьте, что не запущен второй коннектор к NotebookLM |
| `Failed to create ProcessSingleton` | Профиль занят зависшим Chrome: `pkill -f notebooklm-extra/chrome_profile` |
| Пустой список источников при живом блокноте | Узкое окно: интерфейс схлопнулся в табы. Поднимите `NLM_WINDOW_WIDTH` |
| Пустой список источников | Вёрстка изменилась — см. «Починку селекторов» |
| `Кнопка «…» не найдена` | Другой язык интерфейса — переключите NotebookLM на русский или английский |
| Ответ на вопрос не приходит | Дневной лимит запросов NotebookLM либо слишком тяжёлый вопрос |
